## 3. What testing found and what changed because of it

| # | Found by | Finding | Severity | Change |
|---|---|---|---|---|
| 1 | First run | IRR returned None for the base case (bisection bracket) | High | Grid scan then bisection |
| 2 | Reading output | Loan unused; interest ₹0.04 crore | High (model realism) | Debt funds land, approvals and construction |
| 3 | Edge-case test | Sensitivity table had 15 mostly empty columns | Medium (usability) | Positional step columns |
| 4 | Edge-case test | Template memo contained a number absent from the fact sheet | Low | Cushion added to fact sheet |
| 5 | Extra Excel cases | Excel IRR() returned #N/A on the downside case | Medium (benchmark) | Guess argument in formula |
| 6 | Extra Excel cases | Two valid IRRs in the heavy-debt case; tool and Excel reported different ones | High (decision risk) | Non-unique IRR detection and on-screen warning |
| 7 | Detector on base case | First detector flagged the base case because of a root at −98% per year | Medium | Root band restricted to −10% to +50% per month; NPV-sign consistency check |
| 8 | Property tests | My assertion that NPV always falls with the rate was false for loss-making and non-conventional flows | None (model correct) | Test restricted; recorded as a learning |
| 9 | Screenshot review | Tornado colours inverted for cost drivers | Medium (misleading chart) | Colour by metric direction |
| 10 | Screenshot review | Sensitivity table too wide for its column | Low | Shorter step labels |
| 11 | Browser timing | 27.7 s per input change; sensitivity loops ran two break-even solves per appraisal | High (demo would stall) | Break-even skipped inside loops; 1.7 s |
| 12 | Browser test | Edit immediately after Reset lost while widgets remounted | None (test timing) | Test helper verifies and retries |
| 13 | Tooling | Snap LibreOffice cannot write to /tmp; kill pattern matched its own shell | None | Project-local folder; kill by port |
| 14 | LLM memo | First real memo (Sonnet 5.5 via AIML API) said the fact sheet "does not say which assumptions were changed" in the scenarios, so it could not judge their likelihood | Memo less useful | Scenario definitions added to the fact sheet; memo regenerated and re-checked |
| 15 | LLM memo | Memo reported that a 3-month construction delay *raises* NPV (₹7.82 cr vs ₹7.45 cr) and flagged it as counter-intuitive | None in code: the model has no delay penalty, so later spend is discounted more. Correct given the assumptions | Noted as a known limitation in the manual; the memo's caveat was kept |
| 16 | Browser test | On a loaded machine the "Running" status widget appeared 1.2 s after Enter, after the test had already read the stale metric; 3 checks failed although the app was right | Flaky test | Test now waits for the widget to attach before waiting for it to detach |

## 4. What was not tested

- The Anthropic-direct provider with a real Anthropic key. Only its no-key error path was tested; the
  live memo was produced through the AIML API gateway (same prompt, same fact sheet, Claude models).
  Memo text itself was read by a person once (see `docs/llm_memo_claude-sonnet-5-5.md` and
  `docs/llm_memo_claude-opus-5-5.md`); LLM output varies between runs and must be re-read every time.
- Windows and macOS installation. Only Linux was used.
- (Closed 5 Nov 2026.) Streamlit Community Cloud: all 27 browser checks, including the live Claude memo, passed
  against https://ce725-real-estate-feasibility.streamlit.app/ (recompute 3.6 s).
- Browser rendering in Firefox or Safari; only Chrome was used.
- (Closed 5 Nov 2026.) The hand calculation by a person with a calculator is now in section 6 of the
  validation report, re-performed by the Validation Engineer.
